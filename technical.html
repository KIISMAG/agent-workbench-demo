ARCHITECTURE / LIMITATIONS / EVIDENCE

A model reasons.
Validated tools change state.

These are independent demonstration projects built for an AI-agent development portfolio. Business data, supplier proposals, prices and learner answers are fictional. Tool calls, saved state and generated files are real.

The public site is an explorer of completed runs. It does not invoke a model, accept customer data or provide a hosted SaaS service.

Execution architecture

The operator uses Codex for reasoning. A custom MCP server exposes bounded tools over stdio. Node.js validates requests, performs calculations, writes SQLite state and generates PDFs. The current-session bridge is a real MCP client. Separate reviewer results identify their actual canonical Codex task.

The backend has no model API and no unattended agent loop. The local application displays live database state. The public build reads a static export of that evidence.

Three workflows

  • Lead to quote. Catalogue pricing, missing-field clarification, duplicate detection, area-based team capacity, persisted proposal and local operator approval.
  • Document review. Text extraction from three approved PDFs, page-preserving evidence, calculated totals, uncertainty flags and a downloadable report.
  • Adaptive mentor. Three-dimension rubric, exact answer quotations, primary assessment, separate agent review and a next exercise chosen from the weakest reviewed dimension.

What is deliberately bounded

  • PDF extraction supports this text-based source set. Arbitrary uploads, OCR and retrieval over a large knowledge base are outside this version.
  • Capacity is measured in floor area per service date. Travel, time windows and worker skills are outside the demonstration.
  • Duplicate matching uses normalized client name and date.
  • Local actor labels record provenance; they do not authenticate users. The operator application runs on loopback.
  • Two sample learner answers illustrate adaptation. They do not establish learning efficacy.
  • No emails, real bookings or supplier approvals are sent.

Inspect the evidence

Open Tool trace in any scenario to inspect arguments, returned data, errors and timestamps. Source PDFs and generated reports can be downloaded from their case. A JSON export is available for inspection. Videos are recordings of the working browser application with explanatory English captions.

Local setup

Node.js 24+, React, TypeScript, Vite, Node.js built-in SQLite, MCP SDK, PDF.js and pdf-lib. Install dependencies, seed the fictional data, run the backend and Vite, then connect the MCP server to Codex. Full source and local instructions are stored with the owner’s project.
